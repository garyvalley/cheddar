# Cheddar

Personal-finance PWA: accounts, net worth, spending reports, projections, tax-aware ideas.
Architecture, usage and deploy: README.md; tests: tests/README.md; schema: migrations/README.md; cluster: k8s/README.md.
~/dev/CLAUDE.md applies too.

## Stack
Nuxt 4 (`app/`, `server/`) · PocketBase 0.40.6 (`pb_hooks/`, schema in `migrations/` applied by `scripts/migrate.mjs`) ·
production on the home k3s Pi cluster, namespace `cheddar`, public via Cloudflare Tunnel.
Multi-user from day one: every user's data is theirs alone unless they share selected accounts with a household (see Gotchas); state and filing status are per-user settings (all 50 states + DC).

## Commands
- `pnpm run setup` once (PocketBase in Docker on :8095, superuser in `.env` as PB_SU_EMAIL/PB_SU_PASS), then `pnpm dev` (:3005); `pnpm dev:stop` stops PocketBase.
- Demo login (local only, made by setup): `demo@example.com` / `Cheddar-demo-1`; it sets up two-step sign-in on first sign-in like any account.
- `pnpm lint` · `pnpm typecheck` · `pnpm test:unit` · `pnpm test:api` (needs `pnpm dev` and `docker compose up -d nginx`: it runs through nginx on :8085) · `pnpm test:ui` (production build behind a second nginx; tests/README.md has the commands).
- Production build locally: `pnpm build && PORT=3012 NUXT_POCKETBASE_URL=http://127.0.0.1:8095 node .output/server/index.mjs`.
- `node scripts/make-icons.mjs` after changing `shared/mark.ts`; `node --env-file=.env scripts/screenshots.mjs` refreshes README screenshots.
- Current TOTP code for a secret: `node -e "import('./tests/load-hook-module.mjs').then(({loadHookModule})=>{const t=loadHookModule('pb_hooks/lib/totp.js');console.log(t.codeAt('<SECRET>',t.stepAt(Date.now())))})"`.

## Workflow
- Work on a branch, open a PR, wait for every CI job, then merge; `main` deploys once `DEPLOY_ENABLED` is `true`.
- Deploy setup steps that need the user (runner, tunnel, secrets) are in k8s/README.md "First deploy".

## Gotchas
- Import shared TypeScript with the `.ts` extension (`./states.ts`): unit tests run it through Node's type stripping.
- Rules the hooks and the app both apply live once, in `shared/` (`categories`, `overlap`, `splits`): `pnpm gen:hooks` (`scripts/gen-hooks.mjs`, esbuild) builds them into `pb_hooks/lib/gen/` as CommonJS for PocketBase's JSVM, checked in. Never edit `gen/`; a unit test fails when it's stale. Keep those modules pure (no Intl, DOM or Node at load time) and add a new one to `MODULES`.
- Node's type stripping can't erase TS parameter properties (`constructor(readonly x)`): declare fields instead.
- Recent activity is `security_events`, written only by `pb_hooks/glue/events.js` (`record(app, user, kind, e, detail)`, best effort); kinds in `shared/activity.ts` and migrations/0026 must match (a unit test checks). A new security-relevant hook step records one.
- Each full sign-in is a `sessions` row (`pb_hooks/sessions.pb.js`, `lib/sessions.js`): a `routerUse` middleware refuses a person's token without `X-Cheddar-Session` (Nuxt sends it from the `cheddar_sid` cookie; `pocketBaseFor(token, sid)`). Calling PocketBase directly as a person, tests send both (`asPb(c)` in tests/api/helpers.mjs). Sessions end 30 days after sign-in; new bank links and unlinks want the password within 15 minutes (`requireFreshPassword`, `POST /api/auth/confirm-password`).
- The users collection has OTP enabled only because PocketBase refuses MFA without a second built-in method; `pb_hooks/two_step.pb.js` refuses every OTP request. Don't remove either half.
- Password and email changes go only through `pb_hooks/credentials.pb.js`, which checks the current password; it refuses PocketBase's own `request-email-change` (no password). The confirm link goes to `/confirm-email` (template in `migrations/0012_email_change.mjs`).
- `mfa_enabled` is set only by the two-step hooks; the record API can't change it. A locked-out user is reset by a superuser in the admin UI (clear `user_totp.locked_until`; `lockouts` sets how long the next lock lasts, and a right code zeroes it).
- Two-step sign-in is required and enforced by collection rules: every new collection's rules include `@request.auth.mfa_enabled = true` (migrations/README.md).
- Rate limits and the country block live only in nginx (`nginx/nginx.conf.template`); Nuxt has none, so test them through nginx (:8085), not the dev server.
- Only POSTs count toward nginx's limits (`$limit_key`); a GET a page makes as it loads must never be limited.
- nginx's `RESOLVER=127.0.0.11` works only on a user-defined Docker network (compose's, or CI's `cheddar-ci`); on the default bridge every request 503s.
- Docker tmpfs mounts need `mode=1777` for the non-root nginx; the cluster's emptyDirs are already world-writable.
- `server/data/` is not auto-imported: import `attempt`, `storeError`, `sessionFor` explicitly; `server/utils/` is. It's one module per concern (`accounts`, `transactions`, `imports`, `categories`, `budgets`, …) and one per page's read model in `server/data/reports/`; a new report reads through `transactionsBetween()` and `balanceHistory()` (`server/data/transactions.ts`).
- `app/error.vue` replaces `app.vue`, so the title template in app.vue doesn't apply there.
- Backups: Litestream (built from source in `Dockerfile.pocketbase`, the last age-encrypting release) runs as its own `pb-backup` pod on `pb-data` (`k8s/backup/`), applied only when `LITESTREAM_REPLICA_URL` is set, or `BACKUP_SMB=true` (the NAS's SMB share mounted at /replica through an admin-applied PV, `k8s/cluster/backup-smb.yaml`; lines tagged `# smb-only` in the manifest). `scripts/restore-drill.sh` restores it (`--self-test` in CI); the age private key never goes to the cluster.
- Images run as uid/gid 10001 with a read-only root filesystem; anything that writes goes to `/tmp` or `/pb/pb_data`.
- pnpm's `trustPolicy: no-downgrade` refuses some old releases; add a reasoned entry under `trustPolicyExclude` in pnpm-workspace.yaml.
- Stop a local server with `lsof -ti tcp:<port> -sTCP:LISTEN | xargs kill`: without `-sTCP:LISTEN` it also kills the browser connected to it, which loses its cookies and looks like a sign-out bug.
- The preview server's launch config is `.claude/launch.json` (`cheddar`, port 3005), ignored by git: recreate it on a fresh clone.
- Cloudflare sends `CF-IPCountry` and `X-Forwarded-Proto: https` down the tunnel (verified live 2026-11-08); nginx logs `country=` per request.
- A route that answers 204 hands `$fetch` nothing: check it with `useAction().succeed()`, never by `run()`'s return value.
- Bank linking is Plaid, on only with a data key (`DATA_KEYS` or `BANK_LINK_KEY`), `PLAID_CLIENT_ID` and `PLAID_SECRET`. Each link's access token, and each two-step app secret, is sealed with the newest key in `DATA_KEYS` (`v2:<32>,v1:<32>`; `BANK_LINK_KEY` is v1 when it names none) and carries the key's id, so keys rotate: `pb_hooks/lib/data_keys.js`, re-sealed nightly by `pb_hooks/data_keys.pb.js`, steps in k8s/README.md. Recovery codes are an HMAC with it. Links live in `bank_links`, which only the hooks read (all rules null). The routes and sync (`pb_hooks/glue/bank_links.js`) go through the provider the link names (`bank_links.provider`): `pb_hooks/glue/providers.js` lists the contract, `glue/providers/plaid.js` is Plaid's; a new aggregator is one more provider file. Plaid's webhooks reach Nuxt's public `POST /api/webhooks/plaid`, which checks their ES256 signature (`server/data/plaid-webhook.ts`, the key fetched through PB's `GET /api/bank-links/webhook-key`) before PB's unauthenticated `POST /api/bank-links/webhook` syncs the link; links get the webhook address only when `APP_URL` is https (`lib/plaid.js webhookUrl`), and `sync()` points older ones there (`bank_links.webhook`). Deleting a `bank_links` row any way (unlink, account deletion's cascade, admin UI) calls the provider's `remove()` (Plaid's `/item/remove`) from its `onRecordAfterDeleteSuccess` hook: don't call it anywhere else.
- Plaid Link loads from `cdn.plaid.com` and opens in its frame: keep both in the CSP (`nuxt.config.ts`). The container can't reach plaid.com; tests use `tests/api/plaid-mock.mjs` via `PLAID_API_URL`.
- Rules (Settings → Rules, `shared/rules.ts`, built for the hooks): `transaction_rules` (the person's own: words, amount size, account → category, rename, leave out) and `category_rules` (learned per merchant), both all-rules-null, read and written only by `pb_hooks/rules.pb.js` / `glue/rules.js` and `glue/categories.js sort()`. A rule's category beats a merchant rule and is applied on every save (a hand-picked one still wins); rename and leave-out only as a row is created or when the person applies a rule to past rows.
- Only `pb_hooks/categories.pb.js` writes a transaction's `category`, `category_by`, `merchant_key` and `bank_category` (the record API's writes to them are dropped); it sorts every transaction as it saves. The category list is `shared/categories.ts`'s; the hooks read it from its build (below).
- PDF statements: the browser takes the text out with pdf.js (`app/utils/pdf-text.ts`, worker served from `/_nuxt`, so the CSP needs nothing) and sends only that text, marked `%cheddar-pdf-text 1`; `shared/pdf-statements.ts` reads it on both sides. Signs come from CR/DR, the running balance, printed signs (turned round for cards), then section headings. Scanned PDFs have no text and can't be read.
- A statement can be imported into a linked account too. File ids and Plaid ids never match, so rows count as the same money by amount and a date at most 4 days apart: imports skip them (`shared/overlap.ts`), and a sync takes over the imported row and detaches it from its import (`pb_hooks/glue/bank_links.js`, with the same `shared/overlap.ts` built for the hooks).
- On the cluster, use `ssh ubuntu@primary sudo k3s kubectl -n cheddar …`: the Mac's kubeconfig can't reach the API off the home network.
- Overview's net worth, monthly income/spending and investment growth are `shared/overview.ts`. Growth needs past balances: `balance_history` (one row per account per day), written only by `pb_hooks/balances.pb.js` whenever an account's balance is saved (all write rules null). Reports read it through `balanceHistory(s, { dailyFrom })`: daily rows from that month on, and before it the `balance_history_months` view (each account's first and last balance of every month, migrations/0023), which is all the sums need; `tests/api/overview-scale.test.mjs` checks they match the full history. Unlinked accounts get a balance in Settings' Your accounts (`PATCH /api/accounts/:id`), or from an imported statement's closing balance (PDF "Ending/New Balance" or OFX LEDGERBAL, as of the statement's last day, only when newer than the one it has).
- There's no Accounts tab: Settings (`app/pages/settings/index.vue`) is collapsible categories (`SettingsCategory`; all closed on every visit, G's choice, and a `#id` link opens the one holding it). The first, Accounts and banks, holds `BankLinks` (link, update, unlink) and `SettingsAccounts` (every account, linked ones included). Import is `/settings/import`; `/accounts` and `/accounts/import` redirect. `/settings?link=1#linked-banks` opens Plaid at once.
- Investments is `shared/investments.ts` (`GET /api/investments`): the brokerage and retirement accounts' value, growth (Overview's `growth()`, overall and per account) and month-end values. Holdings and allocation (`shared/holdings.ts`, `holdings` collection, written only by the sync's `syncHoldings()`, all write rules null) come from Plaid Investments, billed per link, so only with `PLAID_INVESTMENTS=true` (off by default; CI's PocketBase has it on). An account without positions says why (`HoldingsGap`); `bank_links.holdings` is ok/consent/unsupported, and consent links to `/settings?reconnect=<id>`. A missing price or cost basis is stored as 0 and read as null.
- Projections is `shared/projections.ts`: savings rate from the last 6 whole months (not the current one), debt pace from each card/loan's transactions or else its `balance_history`. The assumptions (years, growth, monthly amount, each debt's payment and APR) are kept only in the browser's localStorage, per user. Each debt's estimate is `debtPlan()`: it says whether the payment was entered or inferred, leaves interest out (and says so) without an entered APR, and gives no date when there's no pace or the balance isn't shrinking. "Pay them off together" is `strategyPlan()` (avalanche / snowball, an extra amount kept in the same localStorage), simulated month by month from each debt's plan payment and APR.
- Taxes' figures are per year: `FEDERAL[year]` in `shared/taxes.ts` and `STATE_TAXES[year]` in `shared/state-taxes.ts` (every wage-tax state + DC, from Tax Foundation's table); `STATES[].incomeTax` and the state table must agree (a unit test checks). Add next year's to both each autumn: from February of a year with no figures, `tests/taxes.test.mjs` fails. A year without figures uses the newest before it and the page says so. `GET /api/taxes?year=` offers this year and last, defaulting to last year until April 15.
- "Today" is the person's own day: `todayFor(s)` (`server/data/profile.ts`) from `users.time_zone` (`shared/time-zone.ts`), never `localToday()` on the server, whose pods run in UTC. The browser saves its zone on first sign-in (`app/middleware/auth.global.ts`); pages use `useToday()`. The hooks have no time zone data: Nuxt sends `today` to the bank-link routes, and `dates.personToday()` takes it only within a day of UTC.
- Needs review (Spending's inbox, `reviewed = false`) leaves out a new link's history: a synced row posted more than 30 days before its link was made gets `history` (`shared/review.ts`, set only by the sync; `pb_hooks/review.pb.js` drops the record API's writes). It's counted and searched like any other; `GET /api/transactions/review` counts both, and Spending's "Review those too" adds them (`history=true` in the address).
- Overview's "Coming up this week" (`OverviewUpcoming`, `GET /api/upcoming`, `shared/upcoming.ts`) is the cash-flow forecast's next 7 days (owned accounts only, as Cash flow) plus price rises from `recurring()`'s `change` in the last 45 days; it loads client-side so it never holds the page.
- Overview's Linked banks card (`BankHealth`, last on the page, `shared/link-health.ts`) judges each link by its last successful sync (36 hours) and its open, counted accounts' balance dates (3 days), never by new transactions; failed and sign-in-needed links get Try again or Sign in again (`/settings?reconnect=<id>#linked-banks` opens that bank's sign-in).
- Spending's Recurring section is `shared/recurring.ts` (GET /api/recurring): spending grouped by `merchant_key`, split by amount, and kept when 3+ charges come at a steady pace. Only categories in its `VARYING` set (utilities, housing, …) may change amount every time; anything else needs two of its last three charges at one price.
- Export your data is `shared/export.ts` (CSVs, `cheddar.json`) zipped by `server/data/zip.ts`. `pb_hooks/export.pb.js` checks the password and hands over what only hooks read (merchant rules); Nuxt reads the rest as the person. A new collection holding someone's data belongs in `ExportData` too; never a token or secret.
- Household sharing is opt-in: `households.members` grants view access only to accounts with `shared_household`; hooks invite verified existing users and require acceptance. Members may edit shared transaction details and review state, but account management, balances, categories, rules and bank links remain owner-only. Overview and Spending include shared accounts; Projections, Taxes, Goals, cash-flow schedules and personal exports use owned records only. Shared custom-category labels are read-only. Add tests for both the Nuxt routes and the PocketBase record rules when changing this boundary.
- An account can be closed (`closed_on`) or left out (`excluded`), both set on an account's Edit in Settings (`PATCH /api/accounts/:id`). Excluded accounts count nowhere: report queries add `COUNTED` (`server/data/accounts.ts`; `transactionsBetween()` in `server/data/transactions.ts` does it for the reports) (picking the account by name still shows it; the export takes everything). Closed ones hold nothing from that day (`asHeld()` in `shared/overview.ts`) but keep their transactions in past reports. A kind change between held and owed turns an unlinked account's balance and history round (`pb_hooks/glue/balances.js`).
- A transaction's `note`, `tags`, `excluded`, and review state stay with its owner; a member of its shared household may also change those fields and `payee` on a shared transaction (tags: G's choice, #106). Sync and import never write them. Other edits go through `PATCH /api/transactions/:id`, checked by `shared/transactions.ts` and the PocketBase update rule. Only the owner can change categories, splits, or delete. A manually added row (`source: 'manual'`, on the owner's unlinked account) can be changed entirely and deleted by its owner. An excluded row is listed but counts nowhere: any new total must skip it (`TX_COUNTED` in `server/data/accounts.ts`, beside the accounts' `COUNTED`).
- A transaction split across categories keeps its parts on itself (`transactions.splits`, `[{ category, amount_cents }]` or null), so it stays one row to imports, syncs and their overlap. Totals count the parts: any new total must run its rows through `expandSplits()` (`shared/splits.ts`), which also counts what a changed amount leaves over in the transaction's own category. `pb_hooks/splits.pb.js` checks every record-API write of them (`checkStored()` in `shared/splits.ts`, built for the hooks). A pending charge's split, name, note and leave-out carry to it as it posts (`carryOver()` in `pb_hooks/glue/bank_links.js`).
- Spending's periods are `periodOf()` in `shared/categories.ts`: week (Monday, `at` its date), month, year, custom (`at=from~to`, at most 5 years). Budgets (`budgets` collection, one per owner and category, `shared/budgets.ts`) are monthly and scaled to the span by `budgetFor()`; they're the person's own, and are compared against Spending's totals, which include shared accounts. Deleting a custom category deletes its budget (`server/api/categories/[id]/remove.post.ts`). Rollover (`budgets.rollover`, `rollover_from` YYYY-MM set when turned on): `budgetsForMonth()` (`server/data/budgets.ts`) adds `carry_cents` from each month since, via `carryInto()`, with the current amount; only a whole month gets it (Spending's month, the plan, Overview). Monthly plan (`/budget`, `GET /api/budgets/plan?month=`, `shared/budget-plan.ts`) edits every budget at once against one month: totals follow the typed amounts, suggestions (last 3 whole months' average, up to whole $10) and moves only fill boxes, and nothing is kept until Save.
- A typed-in balance is out of date after 30 days (property 180): `isStale()` in `shared/accounts.ts`, only on open, counted, unlinked accounts the person owns. Settings marks it and Overview counts them, both in the browser from `/api/accounts`.
- The privacy notice (`/privacy`, `app/pages/privacy.vue`, public) is what Plaid's Developer Policy has people told: what's kept, who sees it, how it's deleted, with Plaid's End User Privacy Policy linked there, on sign-up and beside Link. A change to what's stored, shared or kept (a new processor, a retention change) updates it in the same PR. Move `PRIVACY_UPDATED` (`shared/legal.ts`) with it.
- Terms of Use are `/terms` (`app/pages/terms.vue`); `AppFooter` (Privacy · Terms · Contact) is in both layouts and `app/error.vue`. Sign-up must carry `agree: true`; `users.terms_version` is set only to `TERMS_VERSION` (`shared/legal.ts`, built for the hooks) and `terms_agreed` stamped by `pb_hooks/terms.pb.js`. A signed-in person on an older version sees `/agree` first (`app/middleware/auth.global.ts`): move `TERMS_VERSION` only for a change people should agree to again. Operator name and governing state are `runtimeConfig.public` (`NUXT_PUBLIC_OPERATOR_NAME`/`_STATE`).
- The contact form (`/contact`, `POST /api/contact`, `shared/contact.ts`) has no public address behind it: `pb_hooks/contact.pb.js` keeps each message in `contact_messages` (all rules null, admin UI only, deleted after a year) and emails it to the `CONTACT_TO` secret when set. `/.well-known/security.txt` (`server/routes/`) points its Contact at the form. It's the operator's inbox, not the person's data, so it isn't in `ExportData`.
- Tags (`transactions.tags`, a JSON list or null, `shared/tags.ts`, built for the hooks): at most 10, 30 characters, no quotes, so `?tag=` finds one as `tags ~ '"Tag"'` (case-insensitive). `pb_hooks/tags.pb.js` checks every record-API write. Spending's Tags card is `GET /api/tags` (each tag's money out and in for the period, counted rows only, plus every tag used); the CSV has a Tags column. migrations/0021's update rule names the fields members can't change, so a new field is member-editable unless added there.
- Reports (`/reports`, linked from Spending's header and Overview's chart, not the nav: a seventh tab crowds the phone's tab bar) are `shared/reports.ts`: `GET /api/reports?from=&to=` (YYYY-MM, at most 60 months; default the last 12) and `GET /api/reports/year?year=`, both read through `transactionsBetween(…, { counted: true, merchants: true })` and `expandSplits()`. Year in review compares only the same months of the year before, and only when Cheddar has transactions in most of them.
- Transfers and refunds (#110, `shared/links.ts`, built for the hooks): `transactions.link` (the other row), `link_kind` (transfer/refund), `link_checked`, `link_off` are written only by `pb_hooks/links.pb.js` / `glue/links.js` (record-API writes dropped). Each new row is tried once after it's created; a 5-minute cron (`links_backfill`) tries older ones. `sort()` puts a transfer in Transfers and a refund in its purchase's category (`category_by: 'link'`); a hand-picked category still wins and is never matched. Unlink (`POST /api/transactions/:id/unlink`, owner only) sets `link_off` on both so they're never matched again; deleting one side frees the other.
- Alerts by email (#105, `shared/alerts.ts`, built for the hooks; it re-exports the recurring, cash-flow, link-health and budget pieces the hooks need, so they take one build). `alert_settings` (one per person, owner rules; `checked` written only by `pb_hooks/alerts.pb.js`) and `alert_log` (keys sent, all rules null, 120 days). The `alerts` cron runs hourly (charges, banks) and at 15:00 UTC adds balances, bills, budgets and Monday's summary: the hooks have no time zone data, and that hour is the same day across the US. "Lasting" kinds (balance, bank) keep their key only while the state holds. Only verified addresses get mail; an unconfigured Mailjet counts as sent. Budgets' rollover carry is `withCarry()` in `shared/budgets.ts`, shared with `budgetsForMonth()`.
- Property values (#113, `shared/property.ts`, built for the hooks): `accounts.yearly_change_bp` (basis points, ±5000, property kind only; `checkAccountChange()` drops it when the kind stops being property). `pb_hooks/property.pb.js` moves each open, unlinked property account's balance on to today at 10:30 UTC (`valueAfter()`, compounded by the day), which writes balance_history as any save does; `POST /api/property-values/run` (superusers) runs it by hand.
